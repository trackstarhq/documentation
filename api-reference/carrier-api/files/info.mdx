---
title: "Files"
description: "Raw carrier invoice files with presigned download links"
---

Files are the invoice documents Trackstar collects from a carrier connection: invoice CSVs and PDFs, plus a few files Trackstar builds itself when a carrier has no single invoice file to download (Royal Mail's CSVs and FedEx's credit note history). The files endpoint returns presigned download URLs that expire after 20 minutes.

Each carrier delivers a different set of files. For what each one sends, how the files are named, and inline sample rows and downloadable synthetic CSVs, see [Carrier Sample Files](/api-reference/carrier-api/sample-files/overview).

### Fields

| Field | Description |
| :---- | :---------- |
| `id` | The file's unique ID, used to fetch it from `/carrier/files/{id}`. It is a path that can include a folder (for example `pdf/`), so it is not the same as `file_name` |
| `file_name` | Name of the file, without any folder |
| `created_date` | ISO 8601 timestamp when the file became available in Trackstar. This is when Trackstar saved the file, not when the carrier generated it |
| `updated_date` | Same as `created_date`. A file never changes once it is saved |
| `file_type` | File extension: `csv`, `pdf`, `xlsx` (DPD) or `json` (FedEx). `null` if the name has no extension |
| `download_url` | Presigned download URL (expires after 20 minutes) |
| `download_url_expires_at` | ISO 8601 timestamp when the download URL expires |

Filtering on a `file_type` the carrier never produces returns a `400` that lists the types it does produce.

<Note>
  Raw files can overlap. The same charge can appear in more than one file, for example a FedEx preliminary CSV and its final CSV, or two USPS or DPD downloads that share a boundary date. Each carrier page says when this happens. [Invoice Line Items](/api-reference/carrier-api/invoice-line-items/info) are de-duplicated, so use them if you need totals.
</Note>
