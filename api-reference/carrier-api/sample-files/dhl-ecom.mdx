## Overview

DHL eCommerce delivers invoices as positional CSVs. Each file contains one `HDR` row (invoice metadata) followed by many `DTL` rows, one per shipment. A single `DTL` row may carry values in multiple charge columns; each non-zero charge becomes a separate line item in the Trackstar API.

## Files you'll receive

| File | `file_type` | What it is |
| :--- | :---------- | :--------- |
| Invoice CSV | `csv` | One file per invoice, named by DHL as `{invoice number}_{YYYYMMDD}.csv`. Served exactly as DHL delivers it. |

- **CSV only.** Trackstar doesn't receive a PDF or any other file for DHL eCommerce invoices.
- **Some older files appear twice.** A small number of invoice files first synced before September 2026 are listed twice in the Files API, under the same file name. The copies are identical, and line items are not duplicated.

## Shape notes

- **No header row.** The raw CSV has no column names, and the downloadable sample is headerless too, matching the real file. `DTL` rows always have 79 columns in the fixed order documented in **Fields** below (the index column is the 0-based position). The inline example further down adds column names purely for readability.
- **Line type markers.** Each row starts with either `HDR` (invoice-level) or `DTL` (shipment-level). Only `DTL` rows become line items.
- **The `HDR` row is shorter.** It has 16 columns: index 1 is the invoice date, index 2 the invoice number, and index 11 the invoice total.
- **Multiple charges per shipment.** A shipment can populate `Charge*`, `ZFuel*`, special-handling surcharges, and taxes simultaneously. Each non-zero charge column becomes one line item.
- **Totals reconciliation.** The sum of all `DTL` charges should equal the total at index 11 of the `HDR` row. Trackstar checks this: if the charges miss the total by more than 0.01, Trackstar creates no line items from that file. The raw file is still available from the Files API.
- **Some lines have no pickup date.** Tax and adjustment lines aren't tied to a pickup, so `PUDATE*` can be blank. Trackstar uses the invoice date from the `HDR` row for those lines.
- **Asterisked column names.** Most column names end in `*` as delivered by DHL; preserved as-is.

## Mapping to invoice line items

Each non-zero charge column on a `DTL` row becomes one line item.

| Trackstar field | Source | Notes |
| :-------------- | :----- | :---- |
| `tracking_number` | `Internal_Tracking_Num:` (index 10) | |
| `invoice_id` | `HDR` row, index 2 | |
| `account_id` | `Sold_To*` (index 1) | |
| `transaction_date` | `PUDATE*` (index 8) | Falls back to the invoice date at `HDR` index 1 when `PUDATE*` is blank |
| `charge_description` | The charge column's name | The literal column name, e.g. `ZFuel*` or `ZRM10_VAT_Tax` |
| `gross_cost` | The charge column's value | Same value as `net_cost` |
| `net_cost` | The charge column's value | |
| `id` | `Internal_Tracking_Num:`, invoice number, charge column name | Joined with `_` and base64-encoded. A repeat within one file gets `_1`, `_2`, and so on before encoding |
| `raw` | The 79 named `DTL` values | Plus `Invoice_Number` and `Invoice_Date` from the `HDR` row |
