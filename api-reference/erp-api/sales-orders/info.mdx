---
title: "Sales Orders"
---
A sales order is a commitment to sell goods to a [customer](/api-reference/erp-api/customers/get-item). It contains header fields (customer, dates, totals, addresses) and a list of line items, each referencing an [item](/api-reference/erp-api/items/get-item) via `item_id`. Fulfillment events are recorded as [sales order shipments](/api-reference/erp-api/sales-order-shipments/get), linked back to the order via `sales_order_id`. A kit is a single line marked `is_kit`, with the items inside it nested under `kit_components`; see [Kits](#kits).

### Sales Order Statuses
| Status | Definition
| :----- | :---------------------------------------------------------------
| `pending_approval` | Order is awaiting internal approval before it can be worked.
| `open` | Order is approved and open for fulfillment. On Fulfil, draft, quotation, and provisional orders also read as `open`.
| `partially_fulfilled` | Some, but not all, lines have shipped.
| `fulfilled` | All lines have shipped.
| `on_hold` | Order is on hold and will not be worked until it is released.
| `closed` | Order is closed; remaining open lines were closed without shipping. On NetSuite, an order you cancel through the API reads back as `closed`.
| `cancelled` | Order was cancelled, or deleted in the ERP.
| `other` | Status could not be mapped to a canonical value. See `raw_status`.

### Kits

A kit is one sellable item made up of several others, such as a gift box or a
bundle. How much of this section applies depends on the ERP. NetSuite supports
all of it, including shipping kits whose components are lot- or bin-tracked.
Other ERPs may flag kit lines without listing a kit's contents on the item, or
may not accept component lots when you ship. Linnworks only ships a whole order
at its full quantity, so partial kit shipments are not available there.

On a sales order or a shipment, a kit is a **single line** marked with
`is_kit`. The items inside it are nested under that line as `kit_components`
rather than sitting beside it, so the quantities you read are never double
counted.

```json
{
  "line_items": [
    {
      "line_item_id": "1001",
      "item_id": "500",
      "sku": "GIFT-BOX",
      "quantity": 2,
      "is_kit": true,
      "kit_components": [
        { "line_item_id": "1002", "item_id": "610", "sku": "MUG", "quantity": 2 },
        { "line_item_id": "1003", "item_id": "611", "sku": "COFFEE", "quantity": 4 }
      ]
    },
    {
      "line_item_id": "1004",
      "item_id": "610",
      "sku": "MUG",
      "quantity": 1,
      "is_kit": false,
      "kit_components": []
    }
  ]
}
```

Component quantities cover the whole line: 2 gift boxes means 2 mugs and 4 bags
of coffee. Each component also has its own `line_item_id`,
which is what you reference when you fulfill.

For the catalog view (what goes into one kit, independent of any order) fetch
the item:

```bash
curl https://production.trackstarhq.com/erp/items/500 \
  -H "x-trackstar-api-key: <api key>" \
  -H "x-trackstar-access-token: <access token>"
```

```json
{
  "id": "500",
  "sku": "GIFT-BOX",
  "is_kit": true,
  "kit_components": [
    { "item_id": "610", "sku": "MUG", "unit_quantity": 1 },
    { "item_id": "611", "sku": "COFFEE", "unit_quantity": 2 }
  ]
}
```

`unit_quantity` is the amount that goes into a **single** kit, so it is the
per-order quantity above divided by the number of kits on the line.

#### Shipping a kit

Ship the kit's own line and everything inside it goes out with it:

```json
{
  "sales_order_id": "so_1",
  "line_items": [
    { "line_item_id": "1001", "item_id": "500", "quantity": 1 }
  ]
}
```

If something inside the kit is lot- or bin-tracked, name the lot against the
**component's** `line_item_id`, not the kit's. A kit holds no stock of its own,
so there is nothing to draw from at that level. You only need to list the
components that are tracked:

```json
{
  "sales_order_id": "so_1",
  "location_id": "loc_1",
  "line_items": [
    {
      "line_item_id": "1001",
      "item_id": "500",
      "quantity": 1,
      "kit_components": [
        {
          "line_item_id": "1003",
          "item_id": "611",
          "quantity": 2,
          "lots": [{ "lot_id": "9821", "quantity": 2 }]
        }
      ]
    }
  ]
}
```

On the shipment you read back, each component carries the lots and bins it came
out of:

```json
{
  "line_items": [
    {
      "shipment_line_item_id": "ship_line_1",
      "line_item_id": "1001",
      "item_id": "500",
      "sku": "GIFT-BOX",
      "quantity": 1,
      "is_kit": true,
      "kit_components": [
        {
          "line_item_id": "1003",
          "item_id": "611",
          "sku": "COFFEE",
          "quantity": 2,
          "lots": [
            { "lot_id": "9821", "lot_name": "LOT-20240315", "bin_id": null, "bin_name": null, "quantity": 2 }
          ]
        }
      ]
    }
  ]
}
```

<Note>
  A kit ships as a unit. Where the ERP allows partial shipments, you can ship part
  of a kit line's quantity and the rest later, but you cannot ship some of a kit's
  contents without the others.
</Note>

In NetSuite, kits are not stocked in their own right, so a kit does not appear
in the inventory endpoint. Its components carry the stock.
